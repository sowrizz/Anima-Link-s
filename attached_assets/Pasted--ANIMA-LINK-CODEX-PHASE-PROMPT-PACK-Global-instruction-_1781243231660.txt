# ANIMA-LINK CODEX PHASE PROMPT PACK

## Global instruction to paste at the top of every Codex phase prompt

You are building Anima-Link, a React Native Expo + FastAPI + LLM + SQLite + ChromaDB full-stack MVP.

Before coding, read and follow these reference documents in the repo

* `Anima-Link_2-Person_Build_Phase_Document.docx` — Contains the detailed two-person development plan, implementation phases, feature breakdown, backend/frontend responsibilities, API requirements, and build sequence. Refer to this document as the primary execution roadmap and source of truth for development phases, implementation order, and overall build progression.
* `Pasted markdown.md` — Contains consolidated project notes, requirements, feature descriptions, workflows, and implementation guidance gathered during planning. Refer to this document for additional context, requirements clarification, implementation details, and supporting information.
* `1.pages and details.md` — Contains page-by-page specifications, screen descriptions, user flows, navigation structure, and expected functionality for each app page. Refer to this document when building screens, implementing page behavior, and validating user journeys and navigation flows.
* `3.games.md` — Contains details of the mini-games, gameplay mechanics, objectives, UI expectations, and interaction flows. Refer to this document when implementing game-related features, interactions, and gameplay experiences.
* `Anima-Link_Page_Mockup_Prompts.docx` — Contains UI mockup prompts, layout guidance, visual design directions, screen-generation references, and interface flow guidance. Refer to this document as the primary reference for UI/UX design, screen layouts, visual styling, component structure, and user flow implementation.

Use these documents as the source of truth for:

* product concept
* app pages
* UI style
* game mechanics
* API contracts
* two-person split
* fallback rules
* final demo flow

Non-negotiable rules:

1. Build real first, fallback second.
2. Keep fallback responses with the same API shape as the real endpoint.
3. Do not rename API response fields without updating `docs/API_CONTRACT.md`.
4. Frontend must never invent a different data shape from backend.
5. Backend must provide endpoint stubs early so frontend is never blocked.
6. UI must follow the mature premium Anima-Link style: warm cream background, muted pastel cards, subtle line icons, clean typography, no childish mascot/fantasy visuals unless the internal game mechanic requires it.
7. The sacred demo sentence is:
   `I’ll never finish this assignment. I always mess up before exams.`
8. The final demo backbone is:
   `Home -> Chat/Voice -> LLM analysis -> Memory retrieval -> Companion Council -> Thought Monster -> Camera Mission -> Focus Boss -> Tiny Win -> Thought Graph -> Report/Safety`.

After completing each phase:

* run the app/build/tests where possible
* update `docs/API_CONTRACT.md` if endpoints changed
* update `docs/BUILD_LOG_PERSON_A.md` and/or `docs/BUILD_LOG_PERSON_B.md`
* list what is real, what is fallback, and what still needs integration
* do not leave broken imports or half-created routes
